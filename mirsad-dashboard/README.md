# مرصد · لوحة تحكم وإدارة بيانات

<div dir="rtl">

**الإدارة العامة للتعليم بمحافظة جدة**

</div>

تطبيق ويب مستقل بالكامل لإدارة السجلات: إحصاءات فورية، جدول قابل للبحث
والتصفية والترتيب، وإضافة/تعديل/حذف كامل — مع Firebase خاص به وحده،
ومبني بالكامل على **دليل الهوية البصرية لوزارة التعليم**.

> **مشروع مستقل تمامًا.** لا يشارك هذا المشروع أي كود أو إعداد بناء أو
> مشروع Firebase أو استضافة أو قاعدة بيانات مع أي مشروع آخر في هذا المستودع.
> كل ملفاته محصورة داخل مجلد `mirsad-dashboard/`.

---

## الهوية البصرية

كل لون وخط وعنصر تصميمي في هذا المشروع مأخوذ من دليل الهوية البصرية
لوزارة التعليم. لا يوجد أي لون أو خط مُستحدث خارج الدليل.
مرجع الثوابت البرمجية: `src/brand.ts`، وتطبيقها: `src/styles.css`.

### التدرّجان

- **تدرّج العناوين** `#07a869 → #218caa` — حبّات عناوين الأقسام، ورأس
  النوافذ، والشريطان العلوي والسفلي. هو تدرّج عناوين الأقسام في الدليل.
- **تدرّج الأزرار** `#351375 → #7258a4` — أزرار الإجراءات، وهو التدرّج
  الذي يستخدمه الدليل لأزرار «تحميل».

### الخط

`Helvetica Neue W23 for SKY` بوزنيه المعتمدين — **Bold** للعناوين العريضة
و**Regular** للعناوين الفرعية والنصوص. الخط **مستضاف ذاتيًا** في
`public/fonts/` بصيغتَي WOFF2 و TTF، فلا يعتمد التطبيق على أي شبكة خارجية.

```
public/fonts/
├── HelveticaNeueW23SKY-Bold.woff2       ٤١ ك.ب  (‏٥٥٪ أصغر من TTF)
├── HelveticaNeueW23SKY-Bold.ttf         احتياطي للمتصفحات القديمة
├── HelveticaNeueW23SKY-Regular.woff2    ٤٠ ك.ب
└── HelveticaNeueW23SKY-Regular.ttf
```

> للخط وزنان فقط (٤٠٠ و٧٠٠)، ولذلك لا يستخدم التنسيق أي وزن آخر —
> كي لا يلجأ المتصفح إلى التغليظ الصناعي الذي يشوّه الحروف العربية.

### الشعار

شعار وزارة التعليم في `public/brand/` بنسختين: النسخة الفيروزية الرسمية
للسمة الفاتحة، ونسخة سماوية فاتحة (`#69cee3` من الألوان المساندة) للسمة
الداكنة. يُبدَّل الشعار حسب السمة بدل استخدام مرشّح CSS، حفاظًا على دقة اللون.

### ملاحظات التباين

الهوية مصمّمة للطباعة، وبعض تركيباتها لا تبلغ حدود WCAG على الشاشة.
عولج ذلك **داخل لوحة الهوية نفسها** دون استحداث أي لون:

| الموضع | المشكلة | الحل |
| --- | --- | --- |
| عنوان «مرصد» | الفيروزي على الأبيض ‎٢٫٩:١ | استُبدل بالكحلي ‎١٠٫٥:١ |
| تدرّج العناوين | أبيض على الفيروزي ‎٢٫٩:١ | خُتم التدرّج بالسماوي `#218caa` ‎٣٫٩:١ |
| أزرار الإجراءات | أبيض على الأخضر ‎٣٫١:١ (دون حدّ النص العادي) | التدرّج البنفسجي ‎٥٫٨:١ |
| شارات الحالة | أبيض على تعبئة صمّاء ‎٢–٣:١ | أرضية ممزوجة ‎١٦٪ + نص السمة ‎٧٫٩–٩٫٦:١ |
| رقم بطاقة المراجعة | الرملي نصًّا ‎٢:١ | الرملي للشريط العلوي فقط، والنص بلون السمة |
| التذييل | أبيض على تدرّج فاتح | أرضية كحلية ‎١٠٫٥:١ يعلوها شريط التدرّج |

النتيجة: **٤٤ فحص تباين في السمتين، بلا إخفاق واحد.**

## المزايا

| المجال | التفاصيل |
| --- | --- |
| **الإحصاءات** | إجمالي السجلات، النشطة مع نسبتها، قيد المراجعة، القيمة الإجمالية والمتوسط |
| **الجدول** | بحث نصّي، تصفية بالحالة والتصنيف، ترتيب بأربعة مفاتيح باتجاهين |
| **إدارة البيانات** | إضافة وتعديل وحذف مع تحقّق من المدخلات وتأكيد قبل الحذف |
| **البحث العربي** | يتجاهل التشكيل ويوحّد الهمزات والتاء المربوطة والألف المقصورة |
| **الهوية** | ألوان وخطوط وشعار وزارة التعليم، مطبّقة في السمتين |
| **الواجهة** | عربية RTL بالكامل، سمة فاتحة وداكنة، تصميم متجاوب |
| **الوصولية** | تسميات ARIA، إدارة تركيز، إغلاق بـ Escape، احترام `prefers-reduced-motion` |
| **بلا إعداد** | يعمل فورًا بالتخزين المحلي، وينتقل إلى Firestore عند ضبط المفاتيح |

## التشغيل

```bash
cd mirsad-dashboard
npm install
npm run dev
```

يفتح التطبيق على <http://localhost:5183> ويعمل مباشرة في **وضع التخزين المحلي**
مع بيانات تجريبية — دون أي حاجة إلى Firebase.

## وضعا التخزين

يختار التطبيق مصدر بياناته تلقائيًا عند الإقلاع:

1. **التخزين المحلي** (الافتراضي) — `localStorage`، دون شبكة، مع بيانات تجريبية.
   في هذا الوضع **لا تُحمَّل حزمة Firebase إطلاقًا** (استيراد ديناميكي)، فتبقى
   الحزمة الأساسية ‎~165 كيلوبايت بدل ‎~494.
2. **Firestore** — يُفعَّل تلقائيًا عند اكتمال مفاتيح Firebase في `.env`.

## ربط Firebase (اختياري)

> ⚠️ **أنشئ مشروع Firebase جديدًا خاصًا بـ«مرصد».** لا تستخدم هنا مفاتيح أو
> معرّف أي مشروع آخر. معرّفات هذا المشروع في `.firebaserc`
> (`demo-mirsad-dashboard` و`mirsad-dashboard-prod`) مختارة لتكون مختلفة عن أي
> معرّف قائم، والبادئة `VITE_MIRSAD_` تمنع أي تصادم في متغيّرات البيئة.

```bash
cp .env.example .env
# املأ قيم VITE_MIRSAD_* من إعدادات مشروعك الجديد
```

ثم فعّل **Anonymous Authentication** في وحدة تحكم Firebase — يعتمد عليها
التطبيق لمنح كل متصفّح هوية `ownerUid` تطابق شرط قواعد الأمان.

### النشر

```bash
firebase login
firebase use --add            # اختر مشروع «مرصد» الجديد
npm run firebase:deploy
```

يُنشر من `dist/` إلى موقع الاستضافة `mirsad-dashboard` وحده — مع قواعد
Firestore وفهارسها من هذا المجلد.

## قواعد الأمان

`firestore.rules` تنطبق على مجموعة `entries` فقط، وتفرض:

- لا قراءة ولا كتابة دون مصادقة.
- كل مستخدم يصل إلى سجلاته وحدها (`ownerUid == request.auth.uid`).
- منع تغيير مالك السجل بعد إنشائه.
- تحقّق من الأنواع والحدود (العنوان ≤ ١٢٠ حرفًا، الملاحظات ≤ ١٠٠٠، القيمة ≥ ٠،
  والحالة ضمن `active | pending | archived`) — بنفس حدود `src/lib/validate.ts`
  حتى لا ينجح الحفظ في الواجهة ثم يُرفض على الخادم.
- رفض كل ما عدا ذلك افتراضيًا.

## بنية المشروع

```
mirsad-dashboard/
├── firebase.json .firebaserc firestore.rules firestore.indexes.json
├── .env.example                  متغيّرات VITE_MIRSAD_* وحدها
├── public/
│   ├── fonts/                    خط الهوية (WOFF2 + TTF) مستضاف ذاتيًا
│   └── brand/                    شعار الوزارة بنسختيه
└── src/
    ├── App.tsx main.tsx types.ts
    ├── brand.ts                  ثوابت الهوية: الألوان والجهة والشعار
    ├── styles.css                نظام التنسيق المبني على الدليل
    ├── firebase/
    │   ├── env.ts                فحص المتغيّرات دون تحميل Firebase
    │   └── config.ts             تهيئة Firebase والمصادقة المجهولة
    ├── data/
    │   ├── repository.ts         يختار Firestore أو التخزين المحلي
    │   ├── firestoreStore.ts     طبقة Firestore
    │   ├── localStore.ts         طبقة localStorage
    │   └── seed.ts               بيانات أولية
    ├── lib/                      stats · filter · validate · format
    ├── hooks/                    useEntries · useTheme · useToasts
    ├── components/               8 مكوّنات واجهة
    └── __tests__/                41 اختبارًا
```

تلتزم طبقتا التخزين بالعقد نفسه (`EntryStore` في `types.ts`)، فتبديل المصدر
لا يمسّ أي مكوّن واجهة.
