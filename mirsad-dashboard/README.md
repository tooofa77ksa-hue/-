# قياس اتجاه المتعلمين ١٤٤٨هـ

**الابتدائية الخامسة والستون بعد المائة** — الإدارة العامة للتعليم بمحافظة جدة

نظام مدرسي كامل لإدارة قياس اتجاه المتعلمين: استمارة قياس عامة للطالبات،
ولوحة تحكم إدارية للنتائج والتحليل وصوت الطالبات وإجراءات التحسين،
مع تصدير Excel وتقارير مطبوعة وباركود لكل فصل.

مبني على بيانات المصدر الحقيقية — لا توجد أي بيانات تجريبية في النظام.


### فجوات في البيانات المرفوعة

هذه ليست أخطاء في النظام، بل نقص في الملفات المتاحة، ويعرضها النظام صراحةً:

| الصف | الكشف الرسمي | الاستجابات | الأثر |
| --- | --- | --- | --- |
| الأول | — | — | لا يظهر في النظام |
| الثاني | **غير مرفوع** | ٤٢ | تُحفظ الاستجابات، ويتعذّر حساب نسبة الاستجابة |
| الثالث | ٤٩ (فصلا ١ و٢) | ٤٨ | لا تطابق أي اسم — المستجيبات من فصول أخرى لم تُرفع كشوفها |
| الرابع | — | — | لا يظهر في النظام |
| الخامس | **غير مرفوع** | ٢ | تُحفظ الاستجابات، ويتعذّر التأكيد |
| السادس | ٥٠ (فصلا ١ و٢) | ٤٤ | ٤ مطابقات مؤكّدة و٣٩ محتملة بانتظار مراجعة الإدارة |

لرفع أي كشف ناقص: ضعي ملف PDF في `data/source/` باسم `roster-*.pdf`
ثم شغّلي `npm run etl`.

## خط استيراد البيانات

```
PARSE → NORMALIZE → VALIDATE → MATCH → REVIEW → EMIT → VERIFY
```

`scripts/etl/build_dataset.py` يقرأ المصادر ويُخرج `src/data/dataset.json`
مع تقرير استيراد في `data/import-report.json`.

**كشوف PDF:** تخزّن الحروف كأشكال عربية (Presentation Forms-B) مزاحة إلى
كتل يونيكود أخرى وبترتيب بصري معكوس. الفاكّ في `roster_pdf.py` يعيدها
إلى نصّها الصحيح، ويقرأ ترويسة كل صفحة على حدة لأن الفصل يتغيّر بينها.

**توحيد الإجابات:** وردت الخيارات الثلاثة بـ**١٥ صيغة إملائية مختلفة**
(`اوافق تمااما`, `لا اولفق اطلاقًا`, `اوافق الى حد`…). تُوحَّد للتحليل فقط،
مع الاحتفاظ بالقيمة الخام كما وردت. لم تبقَ أي قيمة غير معروفة.

**المطابقة:** لا يُربط اسم تلقائيًا أبدًا.

| الحالة | المعنى | الربط |
| --- | --- | --- |
| `MATCHED` | تطابق تام ووحيد مع الكشف | يُربط |
| `POSSIBLE_MATCH` | مرشّح أو أكثر يحتاج قرار الإدارة | **لا يُربط** |
| `NEW` | لا مرشّح في كشف صفّها | لا يُربط |
| `LEGACY` | لا كشف رسمي لصفّها | لا يُربط |

الحالات غير المؤكّدة تُراجَع في **مركز مراجعة المطابقة**. لا تُحذف طالبة،
ولا يُدمج اسمان، ولا تُفقد استجابة — ولا حتى المكرّرة.

## قاعدة الحساب

الفرق بين رقمين مهم، والنظام يُظهره في كل شاشة وتقرير:

- **نسبة الاستجابة وغير المستجيبات** تُحسبان على طالبات الكشوف الرسمية
  والاستجابات **المؤكّدة المطابقة** فقط.
- **تحليل الأسئلة ومؤشر الاتجاه** يشملان **كل** الاستجابات المنسوبة للنطاق،
  لأن الإجابات بيانات قياس صحيحة سواء تأكّدت هوية صاحبتها أم لا.
- على مستوى **الفصل** تُحتسب المرتبطة فقط، لأن غير المؤكّدة لا يُعرف فصلها.

### مؤشر الاتجاه

متوسط درجات الأسئلة المقيسة على مقياس ١–٣، بعد تصحيح اتجاه الأسئلة
العكسية بمعادلة `min + max − score`. لا تدخل فيه الأسئلة النصّية ولا
التقويم العام ولا الإجابات المفقودة.

**الأسئلة العكسية** (حُدّدت بقراءة معناها، وكلٌّ منها موثّق في `questions.py`):

| # | السبب |
| --- | --- |
| ٦ | نصّه نفي: عدم مراعاة اختلاف القدرات |
| ٧ | تفضيل مدرسة أخرى لتحقيق أداء أفضل |
| ١٦ | الشعور بالقلق داخل المدرسة |
| ١٧ | احتمال التعرّض للإيذاء |
| ١٩ | مشاهدة سلوكيات غير لائقة |
| ٢١ | الرغبة في الانتقال إلى مدرسة أخرى |

## الأقسام

| القسم | المحتوى |
| --- | --- |
| نظرة عامة | مؤشرات المدرسة، جدول الصفوف، التقويم العام، نقاط القوة وفرص التحسين |
| الصف / الفصل | نفس التحليل في نطاق أضيق، بقاعدة حساب موضّحة |
| تحليل الأسئلة | جدول وتوزيع لكل سؤال بنصّه الأصلي، مع ن والمفقود والمتوسط |
| صوت طالباتنا | النصوص الأصلية، تصنيف قابل للتعديل، الموضوعات الأكثر تكرارًا |
| من الرأي إلى التحسين | دورة كاملة: الرأي ← الإجراء ← المسؤول ← الدليل ← الأثر |
| غير المستجيبات | بحث وتصفية وطباعة وتصدير |
| إدارة الطالبات | إضافة، تعديل، نقل، أرشفة، استعادة — بلا حذف نهائي |
| مراجعة المطابقة | تأكيد أو رفض كل حالة يدويًا |
| الروابط والباركود | رابط عام + رابط لكل فصل، مع QR قابل للمسح |
| التقارير | تقرير المدرسة والصف والفصل، مهيّأ لطباعة A4 |
| الإعدادات | مصادر البيانات، نسخة احتياطية، سجل العمليات |

## الأمن والصلاحيات

- القياس العام لا يعرض أي لوحة أو نتيجة أو أداة إدارية.
- صفحات الإدارة تُحمَّل عند الطلب فقط، فلا تدخل حزمة القياس العام.
- بوابة الإدارة برمز في `VITE_MIRSAD_ADMIN_PASSCODE`.

> **حدّ معروف:** في وضع التخزين المحلي لا يوجد خادم، فبوابة الرمز تمنع
> الوصول العَرَضي فقط. الحماية الفعلية على مستوى البيانات موجودة في
> `firestore.rules` وتُفعَّل عند ربط Firebase: القياس العام يكتب استجابته
> ولا يقرأ استجابة أحد، وبيانات الإدارة تشترط `admin == true`،
> والحذف النهائي ممنوع على مستوى القاعدة نفسها.
