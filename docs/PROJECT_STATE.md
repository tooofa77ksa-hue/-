## نظرة عامة

المستودع يحتوي **تطبيقين منفصلين** يُنشران معًا عبر Firebase Hosting:

| # | التطبيق | التقنية | الخلفية |
|---|---------|---------|---------|
| 1 | منصة «شُعلة لغتي» التعليمية | React 18 + TS + Vite + Phaser | Firebase (Auth + Firestore) |
| 2 | خطة تحسين النهروان (`public/nahrawan-plan.html`) | صفحة HTML مستقلة بلا بناء | **Supabase** (Auth + قاعدة بيانات) |

التطبيقان لا يتشاركان الخلفية ولا الكود. الصفحة الثابتة تُنسخ كما هي إلى `dist/`.

## ما يعمل الآن

### منصة «شُعلة لغتي» (`src/`)

- **المسارات**: `/` (رئيسية) ← `/play/*` (اللعب) ← `/teacher/*` (لوحة المعلمة)، عبر `HashRouter`.
- **تقسيم الحزم**: Phaser لا يُحمَّل إلا داخل `/play`، ولوحة المعلمة لا تُحمَّل إلا داخل `/teacher` (`lazy`).
- **ثلاثة أنماط لعب** في `src/game/modes/`: `rocket_mission`, `squishy_treasure`, `magic_gate`.
- **لوحة المعلمة** (10 صفحات): الرئيسية، الأسئلة، إضافة/تعديل سؤال، المجموعات (Sets)،
  الطالبات، المجموعات (Groups)، الاختبارات، النتائج، الإعدادات.
- **جلسات اختبار برابط مشارَك**: `testSessions` تُقرأ بالمعرّف فقط (`get`) بلا تسجيل دخول،
  والقوائم (`list`) مقصورة على المعلمة.
- **نتائج محمية**: `attempts` تُنشأ بلا تسجيل دخول لكن بتحقق حسابي ومنطقي صارم في
  `firestore.rules` (معرّف حتمي `{sessionId}_{studentId}` يمنع تكرار المحاولة).
- **نصوص الهوية قابلة للتعديل** بالكامل من لوحة المعلمة عبر `gameSettings.branding` بلا hard-coding.
- **حزمة صوت عربية** مولَّدة (voice + SFX) تحت `public/audio/`، مع تحكم يدوي بالمستويات وكتم منفصل.

### خطة تحسين النهروان (`public/nahrawan-plan.html`)

- ملف واحد (2009 سطر) يعمل بوضعين عبر `?mode=`: `dashboard` (عرض فقط، افتراضي) و`admin` (تعديل).
- تسجيل الدخول باسم مستخدم بسيط يُربط داخليًا بحساب Supabase Auth حقيقي.
- تعديل كامل للمؤشرات والبرامج والأولويات والإجراءات وفريق العمل، مع أرشفة/سلة استرجاع (`state.trash`).
- تصدير Excel منسّق عبر ExcelJS بتنزيل حقيقي من المتصفح.
- شعار وزارة التعليم الرسمي (آخر تحديث في `8c9f7c6`).

## العوائق والمخاطر المعروفة

- **سياسات Supabase RLS غير قابلة للتحقق من هذا المستودع.** مفتاح `SUPABASE_ANON_KEY` موجود في
  كود المتصفح، وهذا طبيعي ومقصود في Supabase، لكنه يعني أن الحماية الفعلية تعتمد كليًا على
  سياسات Row Level Security داخل مشروع Supabase نفسه. لم تُفحص ولا يمكن فحصها من هنا.
- **خطر متبقٍ موثَّق في `firestore.rules`**: تعذّر فرض تطابق `studentNameSnapshot` مع
  `participants` بسبب قيد في لغة قواعد Firestore. أقصى أثر: اسم خاطئ على محاولة واحدة مسموحة،
  لا انتحال محاولة طالبة أخرى.
- **لا Cloud Function للتحقق من الإجابات الفردية** داخل `answers` مقابل الأسئلة الحقيقية.
- تحذيرات npm عن حزم قديمة (`glob@10.5.0`, `eslint@8.57.1`) — لم تُرقَّ تجنبًا لكسر المشروع.
