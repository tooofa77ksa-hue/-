# 06 — نموذج التهديد (Threat Model)

## الأصول التي نحميها
1. رصيد الغبار ومستويات العتاد.
2. سلامة المشتريات (لا منح مزدوج، لا منح بلا دفع).
3. نزاهة الجولة (المسافة، الإنقاذ، النجاة).
4. توفّر الخادم واستقراره.
5. سلامة اللاعبين (محتوى مفلتر، لا بيانات شخصية).
6. بيانات الحفظ من التلف أو الضياع.

## المهاجم المفترض
لاعب يشغّل مُستغِلًّا (exploit) على العميل: يستطيع **تنفيذ أي كود على جهازه**، واستدعاء أي `RemoteEvent`/`RemoteFunction` بأي حمولة وبأي معدل، وتعديل سرعة شخصيته وموقعها، وقراءة كل ما في `ReplicatedStorage`.
**الفرضية الحاكمة: العميل معادٍ دائمًا.**

## جدول التهديدات

| # | التهديد | الأثر | الدفاع |
|---|---|---|---|
| T1 | استدعاء Remote المكافأة مباشرة | عملة مجانية | المكافأة لا تُطلب أبدًا — الخادم يمنحها عند نهاية جولة يديرها هو |
| T2 | إرسال قيمة مكافأة/سعر في الحمولة | تضخم | كل القيم من جداول خادمية عبر معرّف؛ الحمولة لا تحمل أرقامًا اقتصادية |
| T3 | إعادة إرسال طلب ناجح (replay) | منح مكرر | `nonce` + نافذة زمنية + سجل مستهلَك خادمي |
| T4 | إغراق Remote (1000/ث) | تعطيل الخادم | token bucket لكل لاعب/Remote + عقوبة تصاعدية |
| T5 | حمولة مشوَّهة (`nil`/`inf`/جدول عميق/نص 1MB) | استثناء أو تلف | باب النوع + باب القيمة + حد عمق وحجم |
| T6 | سرعة/طيران/تخطي الخريطة | مسافة وهمية | نقاط تفتيش خادمية + فحص معقولية السرعة والمسافة + الغنيمة من تقدّم مؤكَّد فقط |
| T7 | إنعاش عن بُعد أو إنعاش شبح | مضاعف مجاني | الخادم يتحقق: مسافة ≤ 8 ستود، الهدف ساقط فعلًا، مدة 2.5s متصلة، شحنة متاحة |
| T8 | استدعاء أفعال الجولة أثناء اللوبي | حالة غير متسقة | باب السياق: كل فعل يفحص طور آلة الحالات |
| T9 | منح المنتج مرتين على نفس الإيصال | خسارة/إساءة | `purchaseId` مفتاح تفرّد + المنح والتسجيل في نفس `UpdateAsync` الذرية |
| T10 | إدعاء «اشتريت» عبر Remote | منتج بلا دفع | التسليم **حصريًا** من `ProcessReceipt`؛ صفر مسارات تسليم أخرى |
| T11 | ازدواج العناصر عبر خادمين متزامنين | تضخم | قفل جلسة (`sessionJobId` + heartbeat) |
| T12 | فشل DataStore يُفقد التقدّم صامتًا | غضب اللاعبين | إعادة محاولة أسية + نسخة احتياطية منطقية + وضع قراءة فقط + تنبيه |
| T13 | استيراد Free Model يحمل backdoor | اختراق كامل للتجربة | حظر السكربتات داخل الأصول + فحص أنماط خطرة + سجل أصول إلزامي |
| T14 | تسريب أسرار في المستودع | اختراق حساب/نشر | صفر أسرار في Git؛ أسرار CI فقط؛ ممنوع `.ROBLOSECURITY` بأي صورة |
| T15 | نص مسيء/معلومات شخصية بين اللاعبين | ضرر وخرق سياسة | `FilterStringAsync` إلزامي لكل نص + لا حقول حرة غير ضرورية |
| T16 | تسريب أسرار التوازن عبر `ReplicatedStorage` | هندسة عكسية للاقتصاد | جداول المنح خادمية فقط؛ `shared/` يحمل ما يحتاجه العرض فقط |
| T17 | استغلال Remote تشخيصي/تصحيحي منسي | منح غير مشروع | ممنوع أوامر المطوّر في الإنتاج + جرد Remotes في كل تدقيق |

## المبادئ الحاكمة
1. **الخادم يحسم كل قيمة اقتصادية.** العميل يرسل نية فقط.
2. **الأبواب الأربعة قبل أي منطق**: النوع → القيمة → المعدل → السياق.
3. **Idempotency في كل منح** مرتبط بمعاملة (شراء، مكافأة يومية، نهاية جولة).
4. **الفشل يُغلق لا يُفتح**: عند الشك ارفض وسجّل، ولا تمنح.
5. **صفر ثقة في الأصول الخارجية.**
6. **لا أسرار في المستودع.** أبدًا.

## ما يُسجَّل (وما لا يُسجَّل)
- ✅ يُسجَّل: معرّف اللاعب الداخلي، اسم الـ Remote، سبب الرفض، معاملة اقتصادية بسببها، نتيجة الإيصال.
- ❌ لا يُسجَّل: أي سر، أي رمز دخول، أي نص حر من اللاعب، أي بيانات شخصية.
